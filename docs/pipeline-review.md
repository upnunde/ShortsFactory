# 쇼츠 제작 파이프라인 검토

## 확정된 제작 기준

1. 운영자가 한국어 주제와 대본을 검수한다.
2. 확정된 영어 대사로 TTS를 먼저 만든다.
3. TTS 오디오의 실제 길이가 장면과 최종 영상 타임라인의 기준이다.
4. 힉스필드는 캐릭터 참조 이미지를 사용해 `3:4` 무음·무자막 장면 영상을 만든다.
5. 장면 영상은 TTS 길이에 맞춰 자르거나 마지막 프레임을 연장한다.
6. FFmpeg가 장면들을 잇고 `9:16` 캔버스에 배치한다.
7. 제목, 자막, TTS, BGM은 최종 합성 단계에서만 넣는다.
8. 완성본을 검수한 뒤 YouTube에 업로드한다.

즉, 힉스필드 결과물은 완성 쇼츠가 아니라 완성 쇼츠 안에 들어가는 장면 소스다. 기본 배치는 상단 25%가 제목 영역이고, 아래 75%가 `3:4` 장면 영역이다. 이 경우 3:4 소스를 자르지 않고 9:16 화면에 정확히 넣을 수 있다.

## 이번 검토에서 바로잡은 항목

- Seedance 요청에 빠져 있던 `aspect_ratio: "3:4"`를 명시했다.
- `480p`로 고정돼 있던 생성 해상도를 480p, 720p, 1080p 중 선택하게 했다. 기본값은 720p다.
- 최종 캔버스를 720×1280 또는 1080×1920으로 선택하게 했다.
- 제목 영역 높이를 18~35%에서 조절하고 미리보기와 실제 FFmpeg 렌더가 같은 값을 쓰게 했다.
- 영상 모델, 생성 해상도, 비율, 예상 초당 단가, 영상당 비용 상한을 생성 캐시 키에 포함했다.
- TTS의 실제 장면 길이뿐 아니라 장면별 단어 경계 추정값도 manifest에 저장해 행동과 자막이 같은 타임라인을 사용하게 했다.
- 최종 영상과 함께 `render-settings.json`을 저장해 당시 채널, 음성, 영상 모델, 해상도, 레이아웃, BGM 설정을 확인할 수 있게 했다.
- 렌더 설정이 바뀌면 프로젝트 서명이 바뀌어 이전 완성본을 그대로 준비 완료로 보지 않게 했다.
- 캐릭터 각도 생성 버튼이 요청 파일만 남기고 실패하던 구현을 실제 이미지 생성 API 호출로 교체했다.
- 채널 프리셋을 추가·선택할 수 있게 하고 말투, 그림 스타일, 기본 BGM, BGM 볼륨을 채널별로 저장하게 했다.
- 캐릭터, TTS, 작성 기준, 영상 생성 설정, 최종 레이아웃의 저장 위치를 채널별로 분리했다. 기존 `default` 채널 파일은 그대로 읽는다.
- YouTube·Instagram·TikTok 앱 정보와 로그인 토큰도 채널별 파일로 분리하고, 업로드 때 현재 프로젝트의 채널 계정을 사용하게 했다.
- 대본 규칙과 충돌하던 YouTube 설명의 강제 질문·해시태그 추가를 제거했다.

## 결과 일관성을 위한 장치

- 진행자와 보조 캐릭터의 정면·다각도 이미지는 채널별 로컬 라이브러리에 한 번 저장한다.
- 영상 생성 때 저장된 참조 이미지를 자동 업로드하므로 매번 다시 등록할 필요가 없다.
- 같은 장소와 같은 캐릭터 조합의 기준 스틸은 캐시해 재사용한다.
- 장면 프롬프트는 동일 인물, 얼굴, 안경, 부리, 볏, 의상, 방을 유지하도록 고정한다.
- 생성 모델이나 해상도, 목소리, 대사, 장소, 캐릭터 구성이 달라지면 장면 캐시를 재사용하지 않는다.

## 남아 있는 품질 한계

Kokoro TTS는 단어별 타임스탬프를 직접 반환하지 않는다. 현재 구현은 TTS 파일의 실제 전체 길이를 기준으로 삼고, 단어 길이와 문장부호를 반영해 단어 경계를 추정한다. 따라서 장면 길이와 음성 싱크는 정확하지만, 단어 단위 행동 시작과 자막 줄 전환은 근사값이다. 단어 단위까지 정확하게 맞추려면 타임스탬프를 제공하는 TTS로 바꾸거나 WhisperX 같은 forced alignment 단계를 추가해야 한다.

참조 이미지를 여러 장 전달해도 생성형 영상 모델이 캐릭터를 픽셀 단위로 완전히 동일하게 보장하지는 않는다. 지금 구조는 기준 스틸 재사용과 캐릭터 참조 묶음으로 변형 가능성을 낮추는 방식이다. 더 강한 고정이 필요하면 캐릭터 전용 LoRA 또는 2D 리깅 애니메이션을 별도 경로로 써야 한다.

힉스필드의 실제 가격은 모델과 요금제에 따라 바뀔 수 있으므로 애플리케이션이 임의의 고정 단가를 사용하지 않는다. 설정에 현재 요금표의 초당 단가를 입력했을 때만 예상 비용 상한을 적용한다.
